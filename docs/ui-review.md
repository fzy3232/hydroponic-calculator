## 1. 结论摘要

1. **骨架成立**：卡片视觉语言、品牌蓝的使用、单列纵向结构都立得住。问题集中在
   **「数据的呈现精度」**与**「层级表达」**，不在布局。
2. **最该修的不是美观问题，而是三处会让人看错的地方**：
   - 术语入口在蓝色 header 上**完全隐形**（用户明确要求的功能，入口权重最低）
   - 鼠标悬停提示**只有"含义"、缺"对种植的影响"**（正是用户点名的需求）
   - 偏差列出现 `-0.0%`、同一列小数位 1/2/3 位混杂 → 用户会怀疑算错了
3. **两位专家独立发现同一个问题**（术语按钮隐形）：UI 设计师 P0-5 与 UX 研究员 P0-1
   从不同路径（像素测量 / 按钮权重对比）得出同一结论，交叉验证成立。
4. **一处产品级洞察**（产品经理）：界面显示"偏差 +0.0%"会让用户把
   **数学拟合精度**误读成**现场投加精度**——而结晶水/纯度/称量误差可造成 >20% 实际偏差。
   这是"算对了却种错"的最大风险，值得单独加一句免责与提醒。
5. **一处技术约束**（架构师）：卡片重排会与 ①~⑥ 步骤编号语义冲突，
   需先定策略再动手，否则是返工。

## 2. P0 — 必须改（6 条，按建议实施顺序）

### P0-1 术语入口在 header 上完全隐形 ★两位专家独立发现

- **来源**：UI 设计师 P0-5 + UX 研究员 P0-1
- **证据**：`style.css:134-141` 全局 `button { background: var(--brand) }`，而 `header` 底色也是
  `var(--brand)` = `#2f6fd0` → 按钮形状消失，只剩白字漂浮。截图中「📖 术语词典」是最不像
  按钮的一个，反而比旁边三个浅灰按钮权重更低。**用户明确要求过"留有地方做解释"**。
- **建议**（用现有色，不新增色相）：
  ```css
  header button {
    background: rgba(255, 255, 255, 0.16);
    border-color: rgba(255, 255, 255, 0.55);
    color: #fff;
  }
  header button:hover { background: rgba(255, 255, 255, 0.28); }
  ```
- **验收**：header 上 4 个按钮都有可见边界；5 秒测试 ≥4/5 能指出术语查询入口。

### P0-2 悬浮提示缺"对种植的影响"（违背用户明确要求）

- **来源**：UX 研究员 P0-2（主理人已核验属实）
- **证据**：`view.js:107` 只拼 `${entry.term}\n${entry.meaning}` —— **没有 impact**。
  而用户原话是"尤其是对种植这件事情的影响"。且 tooltip 只加在 ② 的元素名，
  ④ 的「分域约束/偏差驱动补料」提示、⑤ 的「偏差>10% / 已剔除 / 母液沉淀」提示条
  **全都没有解释入口**——恰恰是用户最困惑的地方。
- **建议**：
  1. `tooltips[element] = \`${entry.term}\n${entry.meaning}\n影响：${impact首句}\``
  2. 结果区提示条尾部加"这是什么？"内联链接，点击打开词典并定位该条
  3. 术语匹配由 `term.startsWith(element)`（顺序敏感、静默失效）改为显式的
     `element → term` 映射表
- **验收**：DOM 断言 `title` 中含"影响"；任务"查螯合铁"≥4/5 在 15 秒内完成。

### P0-3 偏差列 `-0.0%` + 同一列小数位 1/2/3 混杂

- **来源**：UI 设计师 P0-4 + P0-2（UX 研究员亦独立提到 `-0.0%`）
- **证据**：
  - `html.js:213` `deviation.toFixed(1)` 对 −0.04% 输出 `-0.0%`（截图 Mg、Ca 行可见），
    同列另有 `0.0%` → **同一列两种零的写法**
  - `formatQuantity` 按量级切精度（`utils.js:81-94`）→ 达成表同一列出现
    `210.6` / `30.95` / `2.50` / `0.500` / `0.050` / `0.010`
- **建议**：
  ```js
  // 1) 偏差归零
  const rounded = Math.abs(deviation) < 0.05 ? 0 : Number(deviation.toFixed(1));
  const deviationText = `${rounded > 0 ? '+' : ''}${rounded.toFixed(1)}%`;

  // 2) 新增固定精度函数（core/utils.js）
  export function formatFixed(value, decimals = 2) {
    const parsed = toNumber(value, Number.NaN);
    if (!Number.isFinite(parsed)) return '';
    if (Math.abs(parsed) < 1e-9) return '0';
    return parsed.toFixed(decimals);
  }
  ```
  达成表四列统一用 `formatFixed(x, 2)`；**必须整列统一，不能混**。
- **附带修正**：② 的 `<input step="0.01">` 与 3 位小数值（`30.955`）冲突，
  微调箭头会跳到 30.96。要么显示归一到 2 位，要么 `step="0.001"`。
- **验收**：偏差列无 `-0.0%`；达成表数值列小数点在同一竖线上。

### P0-4 用量表出现 `0 / 0` 整行与 `S 0g`、`Zn 0g` 空贡献

- **来源**：UI 设计师 P0-3 + 架构师（阈值双标准，独立发现）
- **证据**：`utils.js:83` 显示阈值 `0.005` vs `html.js:144` 过滤阈值 `1e-6` 不一致
  → "铝酸钠(二水)"显示 `用量 0 / g/L 0` 整行零信息（截图可见），
  贡献列出现 `S 0g、Zn 0g`、`Mo 0g、Na 0g`。
- **建议**：三处阈值统一为 `0.005`：
  ```js
  .filter((item) => item.grams >= 0.005)
  const grams = item.grams * content / 100;
  return grams >= 0.005 ? `${displayName(element)} ${formatQuantity(grams)}g` : '';
  ```
- **理由**：纯噪声行会诱发"我是不是漏了什么料"的误判——这是**错误预防**，不只是美观。
- **验收**：用量表无显示为 0 的行；贡献列无 `0g` 项。

### P0-5 切换作物/生育期静默覆盖用户手改的目标值

- **来源**：架构师（新发现）
- **证据**：`view.js` `syncTargetsFromStage()` 直接 `state.targets = [...crop.target]`，
  无确认、无提示。用户若手改了 16 个元素中的几个，切换一次作物**全部丢失且无感知**。
- **建议**（二选一）：
  - 检测到用户改过（与文献值不一致）时给一次确认
  - 或至少在界面上提示一句"目标已恢复为该生育期文献值"
  另可参考 UI 设计师 P2-7：让 ② 的"参考 X"承担**偏离提示**职责——
  用户改过的格子，参考值高亮为品牌色，形成"你已偏离文献值"的可见状态。
- **验收**：手改目标后切换作物，用户能明确感知目标被替换。

### P0-6 使用说明残留矛盾文案

- **来源**：UX 研究员 P0-4 + 主理人核验
- **证据**：`使用说明.md:27` 写"不用点任何按钮"，而 `:35` 仍写"点「载入目标」，自动填入
  该阶段的营养目标"——**同一文档自相矛盾**，且"载入目标"按钮名已改为"重载目标"。
- **建议**：统一为"切换即自动载入；手改后想恢复文献值，点「重载目标」"。
- **验收**：全文检索"载入目标"无残留。

## 5. 分歧与裁决

**分歧 1：达成表要不要折叠？**
- UX 研究员与产品经理：默认折叠为摘要（信息密度倒挂）
- UI 设计师：不建议删除该表（进阶用户核对需要）
- **裁决**：两者不冲突——**保留表、默认收起**（P1-2）。理由是 UX 与产品从"任务完成"角度出发，
  UI 从"数据完整性"出发，`<details>` 同时满足：默认降低密度，需要时完整可查。

**分歧 2：卡片是否重排/前置？**
- 产品经理与 UX 建议把"三步引导"和结果前置
- 架构师给出**技术约束**：`view.js` 全部经 `byId` 绑事件，与 DOM 顺序解耦（改动成本低），
  但**若把 ⑤ 结果前置到 ① 之前，会与既有 ①~⑥ 步骤编号语义冲突**，属重排返工
- **裁决**：采纳架构师意见——**先加顶部引导文案（P2-11），不动卡片顺序**。
  重排需先由 PM/UX 定编号策略，否则返工。

**分歧 3：测试数量口径**
- 架构师质疑"44 vs 38"不一致
- **裁决**：两个数字都对（运行时 44 / 字面 38，循环生成用例所致）。
  验收信号统一改为"贴出 `node --test` 的 `# tests` 输出"。
